로그인은 이 서버에서 시작됩니다.

실제 판매형 SaaS 제품의 로그인 게이트처럼, 과한 설명보다 로그인 액션과 신뢰 신호가 먼저 보이도록 재구성했습니다. 로컬 계정 로그인과 Keycloak 기반 소셜 로그인 흐름을 같은 화면에서 확인할 수 있습니다.

Access Portal Start Google Broker Flow
Single Entry 브라우저 진입은 auth-server가 직접 받고 로그인 방식 선택을 이 화면에서 닫습니다. GET /login
Brokered OAuth2 auth-server는 Keycloak과만 통신하고 provider 분기는 Keycloak에서 처리합니다. kc_idp_hint = google | github
Token Re-Issue 최종 응답 토큰은 auth-server 기준으로 다시 발급되어 내부 서비스 계약을 맞춥니다. issuer = project-auth-server

현재 인증 흐름

실제 브라우저 리다이렉트와 내부 처리 단계를 짧게 읽을 수 있게 정리했습니다.

runtime flow
  1. 01
    Entry 사용자가 이 페이지에서 로컬 또는 소셜 로그인 진입점을 선택합니다.
  2. 02
    Broker Redirect Spring Security가 Keycloak authorization endpoint로 요청을 넘깁니다.
  3. 03
    Provider Authentication Keycloak이 Google 또는 GitHub 화면으로 브로커링합니다.
  4. 04
    JWT Response auth-server가 최종 사용자 처리 후 자체 JWT JSON 응답을 반환합니다.
